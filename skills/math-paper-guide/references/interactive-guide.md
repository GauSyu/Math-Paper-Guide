# Interactive website delivery

Create a complete paper-guide website that the user can save and open in a browser. Deliver an entry HTML file and any necessary local assets together, with editable site and diagram sources. Prefer self-contained or bundled dependencies that work without a build server. If external resources are needed, state that requirement and test it; do not claim offline portability without checking.

## Paper-guide website

Build the site around the mathematical paper or series: paper title, authors and source version; the problem and relevant prior work; an early logical relationship diagram; connected explanations and source locators. Site navigation, search, card layouts, terminology pages and original-passage indices can help readers explore these materials. Choose visual design and interaction for explanation and navigation; no particular aesthetic or document-like layout is required. Keep a coherent reading route through the site's pages or views.

Use selection, expansion, focus, diagram zoom and search where they help follow an argument or return to the source. Do not default to a learning platform organized around curricula, lesson catalogues, learning tasks, progress tracking or completion badges. Add that structure only when the user asks for it. Suggested reading order should be an optional original-passage index or a route through the mathematical question, rather than a required curriculum.

## Interactions for mathematical reading

Start with a readable overview and a brief account of the problem and relevant prior work. Selecting a result or construction should lead to its statement, hypotheses, explanation and source locator. Selecting an important dependency should reveal what the input supplies at that step and where the use occurs. A dense argument may offer a focused neighborhood or an expanded local proof view. Choose the interactions that help the current guide rather than building a general research dashboard.

Keep stable identities between diagram nodes, explanatory sections and source anchors. Preserve joint inputs, shared dependencies and alternative routes when focusing or expanding the graph. Contextual citation links must remain distinct from proof-use arrows. Keep original terms and result numbers visible, and carry unchecked external statements or applicability qualifications into every relevant view; selection must not imply new verification.

Provide a coherent text reading path alongside the graph. Important statements, conditions and qualifications must be accessible without hover, and the complete guide must remain reachable rather than existing only in transient tooltips. Use native keyboard-operable controls, readable mathematical notation and a layout that reflows on narrow screens. Escape source text so inequalities and other source characters remain content rather than markup.

## Sources and portability

Show the source identity/version and exact statement or proof locator in text even when a local attachment link cannot be opened by the browser. Use working in-document source anchors or appropriate original-source links; include source files or excerpts only within the existing authorized scope. Do not fabricate a working link to unavailable material or replace the original files.

Use available web-authoring, mathematical rendering and browser-inspection tools. A saved full guide needs a standalone website whose reading interactions work in a browser. Local selection and expansion should not require an account or a live model call.

Default to delivering the local entry HTML, assets and editable sources. Creating, previewing or saving an interactive website does not request Site registration, source upload or deployment.

Use ChatGPT Sites private hosting only when the user explicitly requests it and the host provides that capability. Follow its supported source and deployment workflow, verify the requested private audience, and retain the local website and editable sources in the guide's established location. Check hosted links without exposing machine-local source paths; source inclusion still follows existing authorization. If private hosting is unavailable or its audience cannot be confirmed, preserve the local deliverable and report the specific limitation rather than substituting public hosting. A privately hosted guide has the same mathematical content and verification requirements as the local website.

## Check the actual webpage

Open the delivered entry file in a browser. Exercise the important node and edge selections, a local expansion or focus when included, the text reading path and source navigation. Check agreement between the selected details and the diagram, original terminology, mathematical rendering and retained uncertainty. Inspect a narrow and a desktop layout, and check keyboard access to the primary interactions. Report webpage checks and unresolved rendering or interaction issues separately from the mathematical exposition, and report only the behaviors and formats actually tested. Fix broken interactions, clipped labels and unresolved formulas before delivery; a screenshot alone does not establish that the page works. If browser inspection is unavailable, preserve the website and identify the interactions and layouts left untested rather than claiming that they passed.
